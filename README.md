# كازية السلام · منفذ السلامة → منصة «ممر» (MAMAR)

> **أقوى فكرة:** لا تَبْنِ «كازية رقمية»، بل ابنِ **طبقة تشغيل الوقود للممر الحدودي**.
> تحجز المنصة الوقود باسم **لوحة الشاحنة** قبل وصولها، تزامنه مع موعد العبور،
> وتترجم الطلب إلى **أمر توريد مُتتبَّع**، ثم تبيع النظام نفسه لكل المنافذ.
> **كازية السلام في منفذ السلامة هي العقدة الأولى** التي تُثبت النموذج.

**الشعار:** «الوقود يصل قبل الشاحنة… والطابور يصفر.»

النموذج ليس مجرد «صفحة عرض»؛ هو ينفّذ الحلقة كاملة: **حجز باللوحة ↔ تحقق من الحصة ↔ تذكرة QR حقيقية ↔ استدعاء مسار ↔ تعبئة ↔ خصم الخزان ↔ معاملة ومحفظة ↔ تتبّع توريد ↔ مؤشرات ومحاكي جدوى**.

## التشغيل

```bash
python3 app/server.py                 # http://localhost:3000
PORT=8080 python3 app/server.py       # أو أي منفذ
```

ثم افتح العنوان في المتصفح. تعمل الواجهة أيضاً مباشرة في معاينة Arena (الخادم يربط على `0.0.0.0` ولا يشترط مضيفاً محدداً).

- لا حاجة لـ `npm install` أو قاعدة بيانات: الحالة تُحفظ في `app/data/state.json` (مستثنى من Git).
- زر **«إعادة الضبط»** يعيد بيانات العرض؛ مفتاح **«محاكاة حيّة»** يُشغّل وصول المركبات وتقدّم المسارات تلقائياً كل ٧ ثوانٍ.

### تبويبات النموذج

1. **الفكرة** — العرض الكامل، الأدلة، الركائز الست، الرحلة، خارطة الطريق، وروابط المستندات.
2. **السائق / الأسطول** — التوفّر اللحظي، الأسعار، نموذج حجز، وتذكرة QR حقيقية قابلة للمسح.
3. **لوحة المشغّل** — الطابور الذكي، ٦ مسارات، الخزانات وتعديل النشرة، أوامر التوريد (مع مؤقت ٧٢ ساعة)، سجل الأحداث.
4. **الإدارة والجدوى** — مؤشرات الأداء، رسوم الطلب/Mix، **محاكي الجدوى** بمتغيرات قابلة للتحريك، عقود الأساطيل.

### API (للربط مع تطبيق حقيقي)

```
GET  /api/state                       لقطة التشغيل الكاملة + المؤشرات
POST /api/bookings                    إنشاء حجز باللوحة (يتحقق من الحصة واللوحة المكررة)
POST /api/bookings/{id}/call          استدعاء + تخصيص مسار
POST /api/bookings/{id}/start         بدء التعبئة بعد تحقق QR
POST /api/bookings/{id}/complete     إتمام ← خصم الخزان + معاملة + خصم المحفظة
POST /api/bookings/{id}/cancel        إلغاء
POST /api/queue/call-next             استدعاء التالي (الأولوية أولاً)
POST /api/prices                      اعتماد نشرة سعر جديدة
POST /api/tanks/{product}/refill      تسجيل وصول صهريج
POST /api/supply-orders               توليد أمر توريد بصلاحية ٧٢ ساعة
POST /api/tick {"auto":true}          تقدّم المحاكاة
POST /api/reset                       إعادة بيانات العرض
```

## الفكرة في ٦ ركائز

| الركيزة | الأثر |
|---|---|
| الحجز باللوحة (Plate-First) | إلغاء الطابور والدور الورقي |
| الوعد المضمون بالكمية (Quota Engine) | لا يُباع ما ليس في الخزان أو مؤكد الوصول |
| محفظة الأسطول والبطاقة | تحويل المبيعات العابرة إلى عقود B2B |
| توقّع الطلب ↔ أمر التوريد | معالجة أصل أزمة 2026: 50 طلباً نُفّذ من 650 |
| تنسيق المسارات والسجل غير القابل للتعديل | طاقة أعلى، تسوية صفر الفروق |
| **«ممر OS» لشبكة المنافذ** | **من محطة واحدة إلى منصة** |

**السياق (مصادر في `docs/01`):** 1.23 مليون مسافر و46,480 شاحنة عبر منفذ السلامة في ٨ أشهر من 2026، وتوسعة جارية تفصل مسارات الشاحنات وتمدّ أليافاً ضوئية؛ في المقابل طوابير ٤–٥ ساعات وروابط تحميل تنتهي بعد ٧٢ ساعة في أزمة مازوت حلب وإدلب.

## ملاحظات مهمة

- الأسعار والكميات داخل النموذج **توضيحية**؛ في الإنتاج تُسحب «نشرة السعر» من المصدر الرسمي وتُثبَّت على الحجز بختم زمني.
- تكاملا **منصة التوريد المعتمدة** و**مواعيد العبور** معزولان خلف `SupplyAdapter` / `BorderAdapter`، فيمكن البدء يدوياً/شبه آلي دون انتظار واجهات رسمية.
- التصميم يفترض العمل عند انقطاع الشبكة (نسخة edge محلية في المحطة + مزامنة لاحقة)، وقنوات بديلة للسائقين: SMS / واتساب / USSD / kiosk.
- المستودع يحتوي مكتبة QR (`qrcode-generator`، MIT) محلية ضمن `app/public/vendor/` كي تعمل الواجهة بلا إنترنت خارجي.
